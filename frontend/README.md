# Guardian AI - Frontend Dashboard

The frontend of Guardian AI is the user-facing web application where users can view their live mental health analytics, configure their emergency contacts, manage their habits, and generate connection codes to link their chat accounts (Discord/Telegram).

## 🛠️ Tech Stack & Libraries
*   **Framework**: [Next.js](https://nextjs.org/) (App Router paradigm)
*   **Styling**: [Tailwind CSS](https://tailwindcss.com/) & shadcn/ui components
*   **Database**: Live Production Database (PostgreSQL/MySQL integration)
*   **Authentication**: [Auth.js (NextAuth)](https://authjs.dev/)
*   **State & Fetching**: React Server Components & Server Actions

## 🌐 API Routes & Server Actions

The frontend heavily utilizes Next.js Server Actions and API Routes to interact with the database securely:

### API Routes (`app/api/`)
*   **`/api/auth/[...nextauth]`**: Handles Google/Discord OAuth login, session creation, and secure JWT generation.
*   **`/api/user/complete-onboarding`**: A `POST` endpoint that accepts the user's timezone, name, and motivation style, updating their `User` record in the database.
*   **`/api/mood`**: A secure `GET` endpoint that retrieves the authenticated user's `textingBaseline` (which contains analytics generated by the backend LLM) to dynamically render the Burnout, Isolation, and Crisis risk scores on the dashboard.

### Server Actions (`app/(dashboard)/dashboard/habits/actions.ts`)
*   **`createHabit`**: Securely inserts a new `ScheduledHabit`. Includes a hard limit (max 10 habits) to prevent database spamming.
*   **`deleteHabit`**: Deletes a habit, strictly validating that the `userId` of the habit matches the currently authenticated session.

## 🔒 Security Implementations
*   **Strict Authorization**: Every API route and Server Action begins with `const session = await auth()`. If a user is not authenticated, the request is immediately rejected (401 Unauthorized).
*   **IDOR Protection**: All database queries explicitly filter by `session.user.id`. This ensures users can absolutely never access or mutate data belonging to other users.
*   **SQL Injection Prevention**: Safe querying mechanisms are employed to automatically parameterize and escape all inputs, eliminating SQL injection vectors against the live DB.
*   **Spam Prevention**: Hard limits on habit creation prevent users from overloading the database and the backend orchestrator.

## 🚀 Getting Started

1. **Install Dependencies**
   ```bash
   npm install
   ```

2. **Environment Variables**
   Ensure you have a `.env.local` (or `.env`) file in the frontend directory with your required credentials. Based on our setup, you will need the following variables:
   ```env
   # Database Configuration
   DATABASE_URL="file:./dev.db" # Or your PostgreSQL/MySQL URL

   # NextAuth / Auth.js Configuration
   AUTH_SECRET="a_secure_random_string_for_encryption"

   # Google OAuth (For Google Login)
   AUTH_GOOGLE_ID="your_google_client_id"
   AUTH_GOOGLE_SECRET="your_google_client_secret"

   # Discord OAuth & Bot Configuration
   AUTH_DISCORD_ID="your_discord_client_id"
   AUTH_DISCORD_SECRET="your_discord_client_secret"
   NEXT_PUBLIC_DISCORD_CLIENT_ID="your_discord_client_id"
   DISCORD_BOT_TOKEN="your_discord_bot_token"

   # Telegram Bot Configuration
   TELEGRAM_BOT_TOKEN="your_telegram_bot_token"
   NEXT_PUBLIC_TELEGRAM_BOT_USERNAME="your_telegram_bot_username"

   # Caspian Platform Integration
   CASPIAN_API_KEY="your_caspian_api_key"
   CASPIAN_BASE_URL="https://api.trycaspianai.com"
   ```

3. **Run the Development Server**
   ```bash
   npm run dev
   ```

Open [http://localhost:3000](http://localhost:3000) in your browser to see the dashboard.
